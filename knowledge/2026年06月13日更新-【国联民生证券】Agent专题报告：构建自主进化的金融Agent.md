## **1 AI 提升进行时：Harness Engineering**

**随着AI 能力从「回答问题」进化为「执行任务」，搭建投研专属Agent 成为**

**金融工程当下核心需求之一。** 投研专属Agent 需要能找到正确有效的资讯数据，

构建正确的知识链接和推理框架，进行有效全面的投研决策，能够主观+量化的验

证策略效果，并且具有自反馈和迭代进化机制。这一切都需要Harness

Engineering 的设计，本报告将对其展开初步的探索。

### **1.1 “驾驭工程”的本质：AI 管理学**


**当AI 成为代码的生产者，人类工程师的工作将从“写代码”转变为“构建环**

**境、明确意图、设计反馈回路”。** OpenAI 在2026 年2 月11 日发布的报告[1] 揭

示了Agent 时代人类工程师的范式转移：从编码到环境架构；从实现到意图指定；

从调试到反馈循环设计。如果将LLM 比作一匹千里马，那么Harness Engineering

就是指更好发挥马匹效能的马鞍、缰绳、马镫、马蹄铁——这一套“驾驭工程”。

通俗的来说就是从“如何写好代码”转向“如何管好AI 写代码”。


**驾驭工程是在解决日益复杂的AI Agent** **可靠性问题过程中，自然演进的产**

**物。** AI 的工程化实践在近几年经历了三个清晰的演进阶段：


**第一阶段：提示词工程（Prompt Engineering）**


    - 在LLM 应用初期，人们发现通过精心设计提示词，可以显著影响其输出

质量。提示工程的核心在于通过调整措辞、提供示例、设定角色等方式，

引导模型产出更符合预期的结果。


**第二阶段：上下文工程（Context Engineering）**


    - 随着模型上下文窗口的增大和检索增强生成（RAG）等技术的成熟，开发

者意识到，仅靠提示词不足以应对复杂任务。更重要的是为模型提供精准、

全面、结构化的上下文信息。这包括引入外部知识库、管理对话历史、动

态加载相关文档等，构建高质量的信息环境。


**第三阶段：驾驭工程（Harness Engineering）**


    - 面对长链条、多步骤的复杂任务时，即使拥有完美的提示和上下文，AI 内

在的随机性、逻辑推理的脆弱性以及对外部工具使用的不稳定性依然是当

前面临的重要挑战。此时需要构建一个完整的系统来“管理”其工作过程。

通过将模型看作一个需要被精心管理的“引擎”，构建一套包含工具、记

忆、流程、护栏、反馈在内的外部设施，能确保其可靠、可控、高效。

**那么Harness 真正要解决哪些问题？从Agent 的任务需求来看主要有：**


**1、** **Agent Loop：** 执行引擎与决策循环，即AI 的工作流；


**2、** **Agent 记忆：** 知识存储、召回、注入的处理与优化；


**3、** **Agent 优化：** Agent 自身Bug 修复与系统优化；


**4、** **Agent 熵管理：** 随机性与软约束下的系统腐化治理；

**1.2.1** **Agent Loop：ReAct 循环**


**Agent Loop（智能体循环）是当下AI Agent 系统的一种核心运转机制。** 传

统大模型交互类似于信息查询：用户提出问题，模型返回答案，交互即结束。而

Agent Loop 像一位被派去执行任务的“助理”：用户输入目标，如“调研行业并

写一份报告”。它不会立刻开始打字，而是进入一个持续运转的闭环：看到任务 →

思考计划 → 采取行动 → 观察结果 → 调整策略 → 再行动。


这个闭环通常包含四个核心环节：


**感知：** 读取当前环境（用户指令、工具返回的数据、网页搜索结果、报错信息）


**推理：** 分析现状，决定下一步该做什么（调用搜索？写代码？还是直接回答？）


**行动：** 执行具体操作（查资料、运行程序、生成文本）


**关键区别在于第四步——反馈。** 行动之后，Agent 必须看到自己行为产生的

结果，这个结果又会成为下一轮循环的输入，直到达到标准为止。


**Agent Loop 的一个典型案例就是OpenClaw 和Claude Code 底层都依赖**

**的ReAct 循环。** 我们以OpenClaw 为例，它内部嵌入了一个名为PI Coding Agent

的引擎来驱动核心智能。这个引擎运行的就是一个标准的流式ReAct 循环。在这

个循环中，Agent 的每一次思考和行动都被严格编排：Reasoning（思考）→ Acting

（调用工具）→ Observation（解读结果）。OpenClaw 在此之上叠加了多通道消

息入口、向量化语义记忆搜索、Heartbeat 后台守护进程（实现定时任务与主动消

息推送）等机制，使Agent 能够脱离“被动应答”模式，进入“主动服务”模式。

**自动技能生成虽然能让Agent 变聪明** ， **但其是一个内禀熵增过程。** Hermes
Agent 的Skill 库是单向增长的，每次任务执行只往里加新Skill，从不主动减少。

这种“只进不出”的设计在长期会暴露出典型的熵增问题： **近似重复技能堆叠；过**

**度特化一次性Skill；存量Skill 漂移；“Skill 沉积”现象** 。


**自我进化机制必须配对自动清理机制（即熵管理），否则进化的方向可能是“越**

**学越乱”。** 单纯的"加法"能力没有"减法"能力的兜底，时间维度上必然滑向熵增。

OpenAI 在其Harness 思想报告中提出的“熵管理”原则正是为此——部署专用

清理Agent 定期扫描文档漂移、模式违规、依赖问题；Anthropic 的“上下文重

置”机制则定期清空对话历史、仅通过结构化工件传递状态，避免上下文长期积累

导致的焦虑行为与性能下降。


**Hermes** **社区已经意识到这个问题，并给出了名为 Hermes Curator 的解**

**法。** Curator 是一个独立的辅助模型，承担Skill 库的生命周期治理。其核心机制

有三点： **1）Skill 使用遥测：** 为每条Skill 维护被检索次数、被实际调用次数、最

近一次使用时间等指标，长期无人问津的Skill 会被打上标记； **2）生命周期推进：**

Skill 按active → stale → archived 三阶段流转，归档后的Skill 不再注入System

Prompt 但保留备查； **3）周期性巡检与归并：** 周期性扫描全库，识别功能近似的

Skill 簇，调用LLM 合并为一个更通用、更稳健的版本，同时清理冗余分支。


**这对所有“自主进化Agent”的设计都意味：一、进化与清理必须是孪生设**

**计** ； **二、清理机制本身要可解释、可审计。** Curator 做出的合并、归档决策必须留

痕，方便人类回溯“为什么这条Skill 被淘汰了”。否则清理就从“治理”变成“黑

箱遗忘”，反过来动摇用户对Agent 行为的信任。

其中 **MEMORY.md** 作为L1 层的记忆主要提供一个索引，由具体笔记名和简短的

笔记摘要组成，主要是为了方便情境的全局查找。


**而单条情境记忆则与Skill 类似，为YAML 格式头+Markdown 的具体笔记**

**内容。** 单条情境的触发我们尝试过多种方式（固定规则条件匹配情境/RAG 匹配召

回/LLM 全量判断），最终发现由于技术分析下笔记数量有限，直接LLM 自行对

**熵管理的本质是为了对抗Agent 在进化过程中状态漂移导致的系统熵增，相**

**当于自动化的“垃圾回收”。** 具体而言，它针对的是LLM 的三个根本特性：输出不

确定性、上下文腐化、架构漂移与熵积累。

 sector_excluded：对指定股票类型排除

**2.2.5** **自进化机制设计**


**对于Agent** **的自进化，我们借鉴的是GEPA（Genetic-Pareto Prompt**

**Adaptation）算法。** 该算法是Stanford NLP 团队基于DSPy 框架提出的反思式

提示词进化算法[4] ，其本质是将遗传算法与多目标帕累托优化引入Compound

AI 系统的提示词优化，用自然语言反思替代传统RL 的标量奖励信号。


传统RL（如GRPO）将LLM 的完整执行轨迹（推理链、工具调用、编译器报

错、检索结果）压缩成一个标量奖励（打分），再计算策略梯度更新。GEPA 的关

键假设是：这些轨迹本身就是结构化的自然语言，现代LLM 完全具备直接阅读、

诊断和反思这些文本的能力。因此，与其让模型从稀疏的数值奖励中摸索，不如让

另一个LLM（Reflector）直接读取轨迹文本，用自然语言指出失败原因并生成改

进后的提示词。实证来看，在提示词优化中GEPA 的学习效率远大于GRPO。

同时探索覆盖更大的改进空间；然后在验证集上对baseline 和三个候选策略进行

测试，选择最优且好于baseline 的候选策略作为进化方向；最后将新旧策略进行

融合，防止替换带来的历史积累清空和过拟合，用融合提示词在验证集上重跑测试，

若结果明显差于原候选策略，则回滚并放弃本次进化，否则确认提示词变更。

### **2.3 基于Wyckoff 技术分析的自主进化Agent 构建**

**技术分析本身不是量化的标准模型，市场不会按照教科书式的标准模型发展，**

**每个积累或派发形态都有其独特性。** 因此虽然模型可以确立量化的标准进行相关

的统计，但会丢失大量需要用于辅助判断的非标准化上下文信息，就和利用标量进

行优化的GRPO 算法效率低于利用分析文本进行优化的GEPA 算法一样。准确识

别威科夫形态需要大量实践和经验积累，面对一个价格形态，需要结合背景考虑多

种可能性。是否是积累？还是派发？还是中继？每种可能性又分为多种情况。技术

分析的这些层次化的决策特点使得传统量化程序难以有效复刻。


**Model + Harness = Agent 的范式或可以解决其中的难点。** 大语言模型经

过海量文本训练，具备模式识别和理解能力，通过适当的Prompt Engineering，

可以让模型理解威科夫分析的核心原理。而Harness Engineering 提供结构化的

工作流程，引导模型按照威科夫分析的逻辑步骤进行分析，并且可以积累历史分析

案例，在反馈闭环中持续优化。结合程序化所能提供的“硬边界”，Agent 可以获

取实时数据、分析相关形态、即时的验证表现，达到持续进化的效果。


**基于此我们构建了能够自主进化的Wyckoff Agent。** 以威科夫交易方法为核

心分析引擎，通过滚动历史回测构建内生评估信号，再由多角色LLM Agent 协作

完成「预测 → 批判 → 反思 → 进化」的闭环迭代。系统具备情境记忆，能够在

预测时调取历史教训进行动态增强。其有两种运行模式：


 **Mode 1（自学习进化）：** 对某只股票滚动历史K 线，每个窗口做预测并

用实际结果评分，积累足够记录后自动进化分析策略。


 **Mode 2（直接预测）：** 加载已进化的策略，对任意股票的当前或历史时

间点给出结构化方向预测（未来20 交易日）。


**Wyckoff Agent 的核心特点有：**


 **随时间进化**    - 策略可利用历史数据自主迭代，以各种不同类型股票上

的通用判断胜率为核心目标，促进System Prompt 进化，而非静态教科

书式规则；


 **情境记忆增强**    - LLM 根据历史执行轨迹总结特殊情境判断逻辑，预测

时直接判断召回相似历史教训，系统性积累cross-stock 规律；


 **专业分析内核**    - 程序化实现威科夫事件体系 + 多阶段概率估计 +

点数图目标，内核无模糊性，客观刻画市场特征；


 **专属标签适应性**    - 规模/风格/行业标签辅助分类判断。成长股/红利股

等不同股性精准化分类与应用。

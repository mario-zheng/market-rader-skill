CPU 是计算机的“大脑中枢”，架构设计追求“通用性”—— 能够处理各
种复杂逻辑、分支判断、串行任务，是支撑所有系统运行的基础，其核心特点是
“少核心、高主频、强缓存”。CPU 处理操作系统的指令，协调各个硬件组件
的工作，包括内存管理、数据流控制和 I/O 操作。GPU 最初为图形渲染设计，
后因并行计算优势成为 AI 训练、高性能计算的核心。其架构设计追求“并行性”
——采用“多核心、低主频、高带宽”模式，核心数可达数千甚至数万，擅长同
时处理海量相同类型的简单任务。


像 GPT-OSS 和 DeepSeek-R1 这样的大型语言模型（LLM）严重依赖注意
力数据——KV Cache——来理解输入提示并赋予其上下文意义。随着提示长度
的增加，KV Cache 也会增大，也需要更多 GPU 内存（显存，HBM）。当 GPU
内存达到极限时，通常有四种方法解决这一难题：（1）移除部分 KV Cache，

但会导致代价高昂的重新计算；（2）限制提示符长度或上下文窗口，但会降低
模型性能；（3）增加 GPU 数量，但会增加运营成本；（4）将 KV Cache 从
GPU 内存卸载到更具可扩展性和经济性的存储系统，如 CPU 内存、本地 SSD
或远程网络存储。DeepSeek 最新的思路是将实现字典检索功能的 Engram 嵌入
表完全存储在 CPU DRAM 中，减少对显存的占用。


我们认为，显存需求向 **CPU** 内存需求的转移会导致系统对 **CPU** 性能的要
求也相应提高，主要可能体现在：①内存控制器负担： CPU 需要通过其集成的
内存控制器管理 CPU 内存，当 GPU 频繁访问时，CPU 的内存控制器必须处理
更多并发请求，增加了 CPU 的 I/O 负担； ②数据搬运与转换： GPU 访问 CPU
内存时仍需要 CPU 参与内存地址转换和数据格式适配，这会占用 CPU 的计算
资源； ③资源调度复杂性： 在多任务环境中，CPU 需要动态分配内存资源，平
衡 GPU 计算需求与系统其他进程的内存需求，增加了 CPU 调度的复杂度。

# 6.1 大型知识库检索

目标是在不整篇载入大文件的前提下取得足够证据。

## 使用范围

知识库用于整个市场雷达流程，不只用于产品识别：

- 产品确认：产品细分、规格体系和应用边界。
- 工作流 1：BOM、材料构成、材料作用、历史或当前原材料价格。
- 工作流 2：产品价格、产量、开工率、进出口、库存、需求、成交和行业预测。
- 综合判断：产业链驱动、供需解释、库存周期验证和风险背景。

每个研究步骤先检索知识库，再按缺口进行联网搜索。知识库已有满足目标口径和时效要求的数据时可以直接采用，不为增加来源数量而重复搜索。

## 分层读取

1. 知识库固定在本 skill 根目录的 `knowledge/`，所有资料直接平铺为 `.md` 文件，不建立子目录。目录不可访问或为空时记录缺口并转用联网来源。
2. 运行 `python scripts/knowledge_index.py`。脚本默认读取 `knowledge/`，并将索引写入 `data/knowledge-index.json`；只有需要临时测试其他目录时才传 `--root`。
3. 只读取索引中的文件名、标题和 Markdown 标题。根据产品、上位行业、同义词和研究目的选择最多 5 个候选文件，不因为文件都在同一目录而全部打开。
4. 使用 `rg -n -i "关键词1|关键词2" <候选文件>` 定位命中行。每轮关键词应包含产品名、细分类和研究目的词；目的词可包括规格、BOM、原料、价格、产量、开工率、进出口、库存、需求、成交和预测。
5. 初次只读取每个命中点前后约 40 行，每个文件最多 3 个片段。合并重叠片段。
6. 证据不足时，先扩大同一文件的相邻片段，再增加候选文件；不要直接读取整库或整篇超大文件。

## 上下文预算

- 第一轮最多 5 个文件、每文件 3 个片段。
- 优先保留包含定义、表格标题、单位、发布日期和原始出处的片段。
- 同一观点重复出现时保留最原始、最完整的一处。
- 单个文件较短（约 200 行以内）且高度相关时可以完整读取。
- 知识库正式文件统一使用 UTF-8 Markdown（`.md`）。PDF、DOCX 等原始资料应先转成 Markdown 后再放入 `knowledge/`；原始文件可放在 knowledge 目录之外保存，不参与索引。

## 输出要求

知识库证据记录文件路径、报告标题、发布机构、章节标题、行号或页码、发布日期和数据所属期，并标记 `source_origin=knowledge_base`。按照 [05-source-policy.md](../05-evidence-and-failure/05-source-policy.md) 判断置信度：稳定知识不因报告较旧自动降级；市场数据在时效窗口内且口径匹配时可评为高置信度。知识库与联网信息冲突时，区分稳定技术事实和当前市场事实，保留冲突并采用对目标时点更适用的来源。
